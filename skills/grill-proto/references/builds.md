# External builds

Default to two or three credible alternatives. Isolated prototypes need only the focused experiment; app variants reuse the existing app in separate worktrees. Match task, data, context, and polish so each alternative gets a fair comparison.

Use one subagent per variant, in parallel within capacity; build sequentially if unavailable. Supply the decision, assigned direction, settled constraints, shared data, interface, and owned files or worktree. The parent owns shared comparison code. Follow the host's worktree delegation rules; shell-created worktrees do not automatically bind agents.

Start app variants from the same agreed state. Deliberately transfer relevant uncommitted changes: new worktrees do not inherit them. Isolate concurrent ports and mutable data. Keep builds separate from production behavior and simulate external effects.

Run each variant's relevant behavior before presenting it. Briefly disclose unverified behavior or simulation limits that affect the decision.

Give every variant a stable ID and verified direct link in the question. Picker links must open that variant; paths alone are not runnable previews. Keep the runtime available during evaluation. Label revisions, preserve evaluated versions and links, and record which version the user's feedback concerns.
